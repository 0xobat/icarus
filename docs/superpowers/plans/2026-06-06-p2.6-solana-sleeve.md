# P2.6 — SOL / Solana sleeve (jitoSOL) — pricing core + deferred cross-chain

> The design's biggest, most-contained sub-phase, sequenced LAST and explicitly
> kept off the unproven solana-executor. The unit-testable decision-engine core
> is the **Solana sleeve pricing** (SOL + jitoSOL LST, mirroring wstETH). The
> **cross-chain rebalancing** (bridge legs, multi-chain holdings aggregation,
> solana-executor order construction) is a large integration deferred to a
> dedicated Solana execution effort — the same fill-deferral discipline used
> throughout P2, scaled to a second chain.

## Decisions (autonomous, documented)
- **SOL LST = jitoSOL** (jitoSOL-class default from the project parameters).
  Priced like wstETH: `price_usd(jitoSOL) = snapshot jitoSOL/SOL rate × SOL/USD`.
  Non-rebasing → balance constant, value grows via the rate.
- **SOL** priced from the snapshot `SOL` key (the adapter sources SOL/USD).
- **Full 4-asset target** (when Solana lands): USDC 0.40 / ETH 0.24 / wBTC 0.21 /
  SOL 0.15 — the SOL 0.15 reclaimed from the Base-first crypto sleeve. The
  N-asset planner already handles this once SOL holdings + pricing exist.
- **Cross-chain execution is deferred** (the big integration, NOT built here):
  - Solana mint registry (wrapped SOL, Solana-USDC, jitoSOL mints) — distinct
    from the EVM `order_resolver` (which is Base-only by design).
  - Multi-chain holdings aggregation (Base balances + Solana SPL token-account
    balances) into one NAV dict.
  - Cross-chain rebalancing: moving value between the Base and Solana sleeves
    needs a **bridge** (you cannot hub-swap Base-USDC for Solana-SOL directly).
    This is a whole subsystem + the solana-executor; the overview explicitly
    says P2.6 must not ride on the unproven solana-executor. Deferred to a
    dedicated Solana execution phase, with its own fork/devnet run.

## Design (this increment)
- `pricing`: `_LST_RATE_KEY["jitoSOL"] = "jitoSOL/SOL"`,
  `_LST_UNDERLYING["jitoSOL"] = "SOL"`. SOL prices off the `SOL` snapshot key
  (no alias). The existing LST branch handles jitoSOL with zero new code paths.
