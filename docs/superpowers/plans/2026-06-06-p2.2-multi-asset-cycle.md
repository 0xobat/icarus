# P2.2 — Multi-Asset Cycle Migration (data + wiring)

> Wires the P2.1 `plan_multi_rebalance` into the live cycle. Migrates holdings,
> the cycle, config, and `__main__` from the 2-asset `(crypto_usd, stable_usd)`
> tuple to an **N-asset per-asset USD dict** + `MultiAssetTarget`. Keeps the
> live read→plan→gate→publish path green (still no on-chain fill — operator's
> mainnet-fork run, same as P1).

## Re-scope vs. the overview (flag for operator)
The P2-overview listed P2.2 as N-asset migration **+ aToken/LST-aware holdings
+ lending-APY data**. This plan **narrows P2.2 to the pure N-asset migration**
and pushes the other two to where they become real & testable:
- **aToken/LST-aware holdings** → folded into **P2.3 (Aave)** and **P2.4 (wstETH)**:
  until we supply/stake, those balances are 0, so reading them now is untestable
  groundwork. Each execution phase adds its own position read alongside the
  supply/stake it introduces.
- **lending-APY data** → **P2.3**, where net-yield venue selection actually
  consumes it. (At P2.2 there is no venue choice to make.)
This keeps P2.2 a single, fully unit-testable concern, matching the P1 cadence.

## Design

### Holdings — `holdings.py`
Generalize `RpcHoldingsProvider` from a fixed crypto/stable pair to **N symbols**:
- Constructor: `symbols: Sequence[str]` (replaces `crypto_symbol`/`stable_symbol`).
- New method `current_usd_by_asset() -> dict[str, Decimal]` — `balanceOf` per
  symbol (decimals from the registry), priced via `price_usd`, logged as
  `holdings_read` with a per-asset breakdown. Spot ERC-20 balances only (the
  Safe holds spot today); aToken/LST legs arrive in P2.3/P2.4.

### Protocol + cycle — `managed_cycle.py`
- `HoldingsProvider` protocol method → `current_usd_by_asset() -> Mapping[str, Decimal]`.
- `ManagedPortfolioCycle.target: MultiAssetTarget` (was `RebalanceTarget`).
- `run_one`:
  1. `holdings = await self.holdings.current_usd_by_asset()`; `nav = sum(values)`.
  2. **Two-pass cost gate** (the N-asset cost is size-dependent, and the trade
     size is whatever the planner selects):
     - Pass 1: `plan_multi_rebalance(..., est_cost_usd=0, margin)` → if `hold`,
       return hold.
     - Estimate `est_cost` via `estimate_swap_cost_usd(trade_usd=plan1.usd_amount, …)`.
     - Pass 2: `plan_multi_rebalance(..., est_cost_usd=est_cost, margin)` → the
       planner's own cost gate decides hold-vs-go. (Reuses the gate; no
       duplicated logic. Two pure calls, both cheap.)
  3. `_build_order` is already symbol-generic (resolve_swap_params + price_usd) —
     unchanged. RiskContext `cash_usd = holdings.get(target.hub, 0)`.

### Config — `config.py` + `config/managed.toml`
- TOML `[allocation]` gains a `weights` table + `hub`:
  ```toml
  [allocation]
  hub = "USDC"
  [allocation.weights]
  USDC = 0.40
  ETH  = 0.32
  WBTC = 0.28
  ```
- `ManagedConfig`: add `weights: Mapping[str, Decimal]`, `hub: str`; add
  `multi_asset_target() -> MultiAssetTarget`. Validate weights (sum≈1, each>0,
  hub∈weights) — the `MultiAssetTarget` constructor already enforces this; config
  surfaces a clear boot error.
- Retire the single `crypto_symbol`/`stable_symbol`/`crypto_weight` fields and
  `rebalance_target()` (the cycle no longer uses the 2-asset target). The 2-asset
  `RebalanceTarget`/`plan_rebalance` stay in `rebalance.py` (still unit-tested),
  just no longer wired.

### Entrypoint — `__main__.py`
- `RpcHoldingsProvider(... symbols=list(config.weights), ...)`.
- `ManagedPortfolioCycle(... target=config.multi_asset_target() ...)`.
- `_tick`: `holdings = await self._holdings.current_usd_by_asset()`;
  `nav = sum(holdings.values())`; feed drawdown + PnL with `nav` (was
  `crypto_usd + stable_usd`).

### .env.example
No new env vars (weights live in TOML). Per the standing rule, only touch
`.env.example` if a var changes — none here.

## Forward dependencies (documented, not built here)
- **WBTC/cbBTC pricing** in the MarketSnapshot — the adapter must source a
  cbBTC/USD price before WBTC can be valued/traded live. Tracked for P2.3.
  (Unit tests inject prices via the fake adapter, so P2.2 is testable without it.)
