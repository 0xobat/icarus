# P3.2 — Portfolio Health Monitor (de-risk decisions)

> Pure aggregation: given the breaker states + current holdings, decide what
> de-risk actions are warranted each tick. Wired into the tick to surface
> `derisk_signal` events. Emitting the urgent de-risk *orders* is execution
> (deferred to fill), but the DECISION is the testable safety core that satisfies
> the design's exit criterion ("a simulated depeg/health event triggers the
> correct de-risk").

## Decisions (autonomous)
- De-risk semantics by signal:
  - **USDC depeg tripped** → `halt_all` (every rebalance touches USDC; the
    DepegChecker already enforces the halt at the gate — the monitor surfaces it).
  - **LST depeg tripped** (P3.1) for a held LST → `exit_position(asset)`: unwind
    the discounted LST back toward the hub (targeted, not halt-all).
  - **Venue unhealthy** (a venue in `unhealthy_venues`) holding assets →
    `exit_position(asset)` out of that venue.
- Only emit an action for an asset actually held (`holdings[asset] > 0`).
- Pure + deterministic: `assess(...)` returns an ordered `list[DeRiskAction]`;
  `halt_all` first (most severe).

## Design
- `decision_engine/health_monitor.py`:
  - `DeRiskAction(kind: "halt_all"|"exit_position", reason, asset=None)`.
  - `PortfolioHealthMonitor(usdc_depeg, lst_breakers: Mapping[str, LstDepegBreaker])`
    with `assess(*, holdings, venue_by_asset=None, unhealthy_venues=frozenset())
    -> list[DeRiskAction]`.
- Wiring (`__main__._tick`): build the monitor; each tick feed the LST breaker(s)
  when the snapshot carries both the LST market price and its fair value (else
  skip, like the USDC feed), call `assess`, and log a `derisk_signal` event per
  action. Urgent-order emission for `exit_position` is deferred to the fill run.

## Tasks (TDD)
- healthy → no actions; USDC depeg → halt_all first; LST depeg on a held LST →
  exit_position(asset); LST depeg on an un-held LST → no action; unhealthy venue
  holding an asset → exit_position; severity ordering (halt_all precedes exits).

## Out of scope
- Emitting the urgent de-risk orders + the saga to unwind → fill-run integration.
- Live venue-health feed (TVL/pause oracle) → uses the existing tvl_monitor as a
  follow-on; P3.2 takes `unhealthy_venues` as an injected set.
