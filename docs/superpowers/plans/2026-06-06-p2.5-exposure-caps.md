# P2.5 — Per-venue / per-asset Exposure Caps (real position tracking)

> Re-introduce the exposure control deferred at the P1 gate right-sizing
> ([[managed-gate-exposure-decision]]) — but **purpose-built for the managed
> model with real per-tick positions**, not the lake-era `ExposureLimiter`
> (which was position-blind and a category error here). New checker + tests;
> wired into the managed gate.

## Why a new checker, not the legacy one
The legacy `ExposureLimiter` (kept in tree, untouched) takes float/dict orders,
env-driven caps, and `_positions` that were never registered (`current_pct`
always 0 → it only ever capped single-order size). The managed model has a clean
per-asset USD dict every tick; the new checker consumes that directly.

## Decisions (autonomous, documented)
- **Two caps, evaluated on the *prospective post-trade* holdings:**
  - **Per-asset concentration cap** — no asset exceeds `max_asset_pct` of NAV.
    Set **≥ the largest upper band** so it never blocks a legitimate rebalance:
    USDC target 0.40 + band 0.10 = 0.50 upper → default **0.60** (matches the
    lake-era 60% asset notion, and ≥ 0.50). This is a **safety net** against a
    bug / extreme drift, above the band the planner already enforces.
  - **Per-venue cap** — no *capped* venue exceeds `max_venue_pct` of NAV
    (default **0.25**, the toml `per_venue_cap`). **Core lending of allocation
    assets is NOT capped** — it's governed by the allocation bands (USDC 0.40 +
    cbBTC 0.28 ≈ 0.68 on Aave is *intended*). The venue cap therefore applies to
    **overlay venues** (the P3 LP overlay, perps); `capped_venues` is empty until
    P3 wires the LP venue, so the per-venue mechanism ships here but binds later.
- **Real per-tick registration** closes the P1 gap: the cycle computes the
  prospective holdings (current dict with the plan's leg applied) and the
  venue-by-asset map, and threads them on `RiskContext`. No static capital var.
- **Fail-open only on absent data** (legacy/unpriced callers that don't set the
  prospective holdings) — when present, a breach is a hard reject.

## Design
- `RiskContext` gains `prospective_holdings: Mapping[str, Decimal] | None` and
  `venue_by_asset: Mapping[str, str] | None` (both default None → checker passes).
- New `decision_engine/risk/managed_exposure.py`:
  `ManagedExposureConfig(max_asset_pct=0.60, max_venue_pct=0.25)` +
  `ManagedExposureChecker(config, *, capped_venues=frozenset())` with
  `name="managed_exposure"` and `check(order, ctx) -> RiskDecision`:
  - no `prospective_holdings` or `nav<=0` → pass.
  - any asset `usd/nav > max_asset_pct` → reject ("asset concentration").
  - any `v in capped_venues` with summed `usd/nav > max_venue_pct` → reject.
- `risk_gate.py`: import + re-export the checker (gate composition is unchanged).
- `managed_cycle.py`: compute `prospective_holdings` (apply the plan leg to the
  holdings dict) + pass a `venue_by_asset` (from cycle config) on `RiskContext`.
- `config.py` + `managed.toml`: `[limits]` → `max_asset_pct` (new, default 0.60)
  + reuse `per_venue_cap` as `max_venue_pct`; build the checker in `__main__` and
  add it to the managed gate after the cheap breakers.
- Venue map: USDC/cbBTC → `aave_v3`; WETH/wstETH → `wallet`. From a default in
  config (overlay venues added at P3).
